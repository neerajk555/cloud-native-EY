# Lab 4.3: Exposing a Service via ALB

**Cost:** ⚠️ ALB hourly cost, minimal for lab duration
**Time:** ~15 min

## Objective

Expose a service externally via an AWS Load Balancer Controller-managed ALB, correctly tagged.

## Prerequisites

- Lab 4.2 complete
- AWS Load Balancer Controller installed cluster-wide by instructor
- `$PARTICIPANT` is exported for this session (see `SETUP-UBUNTU.md`)

## Steps

### Step 1: Annotate the service for ALB + required tags

```bash
kubectl annotate service web-$PARTICIPANT -n ns-$PARTICIPANT \
  service.beta.kubernetes.io/aws-load-balancer-type=external \
  service.beta.kubernetes.io/aws-load-balancer-additional-resource-tags="Owner=$PARTICIPANT,Course=cloudnative-agentic-ai-2026"
```


### Step 2: Change the service type

```bash
kubectl patch service web-$PARTICIPANT -n ns-$PARTICIPANT -p '{"spec":{"type":"LoadBalancer"}}'
```


## Expected Result

`kubectl get svc web-$PARTICIPANT -n ns-$PARTICIPANT` shows an external ALB hostname, and the ALB in the console carries `Owner`/`Course` tags.

## Cleanup

```bash
kubectl patch service web-$PARTICIPANT -n ns-$PARTICIPANT -p '{"spec":{"type":"ClusterIP"}}'
```

## Troubleshooting

- **ALB created untagged / denied**: The `aws-load-balancer-additional-resource-tags` annotation is required — Kubernetes' cloud provider does not auto-tag ELBs, and the boundary denies untagged ALB creation.
