# Lab 2.3: Asynchronous Events with EventBridge

**Cost:** ✅ Free Tier
**Time:** ~15 min

## Objective

Trigger a Lambda function from a custom EventBridge rule, using the shared EventBridge execution role.

## Prerequisites

- Lab 2.1 complete
- `$PARTICIPANT` is exported for this session (see `SETUP-UBUNTU.md`)

## Steps

### Step 1: Fetch the shared role

```bash
ebRoleArn=$(aws iam get-role --role-name course-eventbridge-lambda-execution --query "Role.Arn" --output text)
```


### Step 2: Create a rule

```bash
aws events put-rule --name demo-rule-$PARTICIPANT --event-pattern "{\"source\":[\"demo.$PARTICIPANT\"]}"
```


### Step 3: Add the Lambda as a target

```bash
aws lambda add-permission --function-name hello-$PARTICIPANT --statement-id eb-$PARTICIPANT --action lambda:InvokeFunction --principal events.amazonaws.com
fnArn=$(aws lambda get-function --function-name hello-$PARTICIPANT --query Configuration.FunctionArn --output text)
aws events put-targets --rule demo-rule-$PARTICIPANT --targets "Id=1,Arn=$fnArn"
```


### Step 4: Fire a test event

```bash
aws events put-events --entries "Source=demo.$PARTICIPANT,DetailType=test,Detail={}"
```


## Expected Result

CloudWatch Logs for `hello-$PARTICIPANT` show an invocation shortly after the test event.

## Cleanup

```bash
aws events remove-targets --rule demo-rule-$PARTICIPANT --ids 1
aws events delete-rule --name demo-rule-$PARTICIPANT
```

## Troubleshooting

- **Rule never fires**: Confirm the event `source` field exactly matches the rule's event pattern.
