# Lab 10.1: Auditing Your Own Least-Privilege Access

**Cost:** ✅ Free
**Time:** ~15 min

## Objective

Use IAM policy simulation to understand exactly what your own permissions boundary + grant allow, since you cannot create a new IAM user or role to experiment with.

## Prerequisites

- Module 1 complete
- `$PARTICIPANT` is exported for this session (see `SETUP-UBUNTU.md`)

## Steps

### Step 1: Get your own ARN

```bash
myArn=$(aws sts get-caller-identity --query Arn --output text)
```


### Step 2: Simulate an allowed action

```bash
aws iam simulate-principal-policy --policy-source-arn $myArn --action-names lambda:CreateFunction --resource-arns "*"
```


### Step 3: Simulate a denied action

```bash
aws iam simulate-principal-policy --policy-source-arn $myArn --action-names iam:CreateRole --resource-arns "*"
```


## Expected Result

The first simulation returns `allowed`; the second returns `explicitDeny`, naming the boundary statement responsible.

## Cleanup

```bash
Nothing created.
```

## Troubleshooting

- **Simulation always says implicitDeny**: That's expected for any action with no matching Allow statement at all — it's a different result from an explicit Deny, and worth noticing the difference.
